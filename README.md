# Hermes Launcher

Локальная панель Hermes Agent для Windows: интерактивный терминал, модели, профили проектов и история сессий.

## Запуск и сборка

```powershell
npm install
npm start
npm test
npm run dist
```

Portable EXE создаётся в `dist`. Hermes и нужный провайдер должны быть установлены отдельно. Путь к Hermes определяется через PATH или стандартную папку `%LOCALAPPDATA%\hermes\bin`; его можно указать в настройках. Нужна Windows с поддержкой ConPTY.

## Работа

1. Укажите проект, провайдера и модель. Для Ollama / LM Studio можно получить список моделей; имя также можно ввести вручную.
2. Откройте «Настройки», задайте лимит ответа, системный промпт и режим подтверждения действий.
3. «Запомнить профиль» сохраняет настройки для папки. Переключение сохранённого проекта восстанавливает профиль; «Сохранить настройки» обновляет его.
4. «Запустить» открывает интерактивную сессию во встроенном терминале. Ввод с клавиатуры, ANSI-цвета и изменение размера поддерживаются. Одновременно работает одна сессия.
5. «Остановить» завершает процесс терминала. Закрытие приложения также завершает его процесс; для штатного выхода Hermes используйте `/exit` в терминале.
6. Найдите сессию по названию или ID и нажмите «Продолжить» либо дважды щёлкните по ней. Удаление требует подтверждения.

## Параметры и ограничения

- Лимит ответа передаётся через `HERMES_MAX_TOKENS`, системный промпт — через `HERMES_EPHEMERAL_SYSTEM_PROMPT`. Пустой промпт оставляет стандартное поведение Hermes.
- Контекст Ollama перед запуском записывается штатной командой `hermes config set` в `model.context_length`, `model.ollama_num_ctx` и `auxiliary.compression.context_length`. Это настройки Hermes, общие с его другими запусками. Минимум в панели — 64000, как в предыдущей версии.
- Поле температуры удалено: установленный Hermes не предоставляет общего параметра температуры чата. Параметры конкретной модели задаются средствами провайдера.
- API-ключи хранятся локально в файле `api-keys.json` с использованием системного хранилища `safeStorage` (или в защищённом кодировании base64 при его недоступности).
- Имя LM Studio по умолчанию — `lmstudio-launch`, совместимое с прежним лаунчером. В настройках укажите фактическое имя вашего провайдера Hermes. API списка моделей: `http://127.0.0.1:1234/v1/models`.
- Для другого локального сервера укажите имя настроенного провайдера Hermes и OpenAI-совместимый URL для получения моделей. Этот URL не меняет адрес инференса в Hermes.
- Выгрузка моделей выполняется явной кнопкой и не вызывается при переключении провайдера. Для Ollama сохраняется полное имя вместе с тегом.
- Список сессий ограничен последними 50 записями; разбор рассчитан на текстовый формат установленного CLI.
- Проверка версии показывает фактический вывод Hermes и не объявляет отсутствие обновлений без подтверждения. Обновление выполняется через `hermes update --force-venv`.
- Старые поля команд остаются в конфигурации для совместимости данных, но больше не исполняются: запуск и служебные операции используют фиксированные команды с отдельными аргументами без shell.
- Настройки находятся в Electron userData (`%APPDATA%\hermes-launcher\config.json`), записываются через временный файл. Повреждённая конфигурация не перезаписывается автоматически. Файл `config.yaml` в проекте — справочный, панель его не читает.

## Структура

`main.js` — окно и IPC; `preload.js` — ограниченный API интерфейса; `lib/config.js` — настройки; `lib/commands.js` — Hermes CLI; `lib/providers.js` — списки и выгрузка моделей; `lib/terminal.js` — жизненный цикл процесса; `renderer/` — пользовательский интерфейс (`renderer.js` — точки входа и bootstrap, `renderer/modules/` — модули состояния `state.js`, IPC-вызовов `api.js`, уведомлений `notify.js`, чистой логики `logic.js`, диалогов `dialogs.js`, формы конфигурации `config-form.js`, работы с сессиями `sessions.js` и терминала `terminal.js`).

`npm test` проверяет запуск/остановку и конкурентные запуски, аргументы со спецсимволами, сохранение и повреждение настроек, а также соответствие IPC. Проверки не запускают агента и не меняют настройки Hermes.

## Проверка интерфейса и автономная сборка

`npm run test:electron` проверяет настоящий PTY и интерфейс в скрытом окне с тестовыми данными, без запуска агента. После сборки `npm run test:packaged` проверяет те же сценарии на ресурсах из `dist/win-unpacked/resources/app.asar`.

`npm run dist:dir` создаёт папку `dist/win-unpacked` с готовым `Hermes Launcher.exe`. Для переноса нужна вся папка. Этот вариант использует установленный Electron и не требует загрузки NSIS. Однофайловый `npm run dist` дополнительно загружает NSIS с GitHub; при недоступности сервера используйте сборку папкой. EXE не подписан; этап изменения ресурсов EXE отключён, чтобы сборка не требовала прав создания символьных ссылок. Подготовка ConPTY DLL выполняется автоматически перед запуском и сборкой.

Для релизов используйте [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md). Там собран минимальный чек-лист перед публикацией, проверка версии и диагностика артефактов. Перед выпуском обязательно актуализируйте [CHANGELOG.md](CHANGELOG.md) и убедитесь, что раздел Unreleased и версия релиза присутствуют.

Вывод проверки версии сокращён до номера версии. Ошибки и служебные подробности доступны в сворачиваемом блоке «Диагностика проверки версии Hermes» и не занимают основную панель. Ошибка UnicodeDecodeError относится к установленному Hermes; её причина в самом Hermes этим изменением не устраняется.
